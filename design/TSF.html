You've nailed it exactly — and that's the crux of porting any custom design to Squarespace. One refinement, though: it's not all dormant.

What IS biting right now

A few rules in the file target Squarespace's real elements, so they're already working:

  • body, h1–h4, p, em (the crimson italic emphasis)
  • .sqs-button-element--primary / .sqs-block-button-element--medium (the buttons)
  • The :root tokens (usable by anything you add later)

What's dormant (your point)

Everything keyed to custom classes — .hero, .recipient-row, .kpi-strip, .pillar-card, .foot, .story-toc — has nothing to attach to. Squarespace emits .sqs-block, .fe-block, .header-nav, etc.

Three ways to close the gap — use the right one per piece

  1. Panels (no classes needed): global type and color come from Design → Fonts / Colors. Do all your typography + palette there. This replaces a big chunk of the dormant CSS automatically.
  2. Section/Block IDs + native selectors: build a section natively in Fluid Engine, give it an ID (Edit Section → Advanced → section id), then scope CSS to it: #donate { … }. Great for backgrounds, color bands, spacing on native layouts.
  3. Code Blocks (full fidelity): paste self-contained HTML that carries your classes — then your component CSS matches it exactly. This is the only way to reproduce the bespoke pieces 1:1 (recipient rows, KPI strip, the V-seal, social row).

Recommended hybrid

  • Type + color → panels.
  • Overall page layout / simple sections (hero, mission, CTA bands) → native Fluid Engine + a little ID-scoped CSS.
  • Signature components → Code Blocks with the original markup.

The Edit button not working on the homepage

This is almost always browser-side, not your site:

  1. Hard refresh — Cmd/Ctrl + Shift + R.
  2. Disable extensions — ad blockers and privacy extensions break the Squarespace editor. Try an Incognito/Private window (with extensions off).
  3. Make sure you opened the homepage itself (Pages panel → click the home page) before hitting Edit (top-left).
  4. If it's a stacked/index or special page type, you edit the individual sub-page, not the container.
  5. Still stuck? Log out and back in, or try a different browser — Squarespace's editor is finicky in Safari sometimes; Chrome is most reliable.

2. Navigation underline → crimson

Squarespace doesn't expose the nav underline color in a panel, so target it with CSS:

/* active + hover nav links */
.header-nav-item--active a,
.header-nav-item a:hover {
  color: #8C1A1A;
  text-decoration-color: #8C1A1A;
}
/* if your nav uses a bottom-border underline instead */
.header-nav-item--active a {
  border-bottom: 1px solid #8C1A1A;
}

3. Button won't go crimson — here's why

Assign Styles only controls the button's font, never its color. Button fill color comes from the section's color theme, not Assign Styles. Two fixes:

  • Proper way: Design → Colors → open the theme that section uses → set the Button color to #8C1A1A. Buttons inherit their fill from the section theme.
  • Override (safety net): add this to Custom CSS —
.sqs-block-button-element--medium,
.sqs-button-element--primary {
  background-color: #8C1A1A !important;
  color: #ffffff !important;
}

If it's still not crimson after the CSS, your button is likely a Secondary/Tertiary style — change it to Primary on the button block, or swap --primary in the selector above for --secondary.
